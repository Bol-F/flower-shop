# OAuth, payments, storefront, and admin QA — 7 October 2026

## Result

319 backend tests and 51 frontend tests passed. Ruff, ESLint, TypeScript,
format checks on edited source files, and the Next.js production build passed.
Django system checks reported no issues; migration detection found no changes.
Existing Django/Redis deprecation warnings remain.

Backend tests used isolated SQLite data and fresh temporary folders. The first
full run encountered a Windows permission error in pytest's existing temporary
folder; the subsequent fresh-folder runs passed. User databases were not seeded
or modified. Temporary QA servers were stopped after verification.

## Browser checks

The frontend-testing/debugging and React best-practices skills guided the
rendered checks, stable OAuth effect dependencies, and browser-storage recovery.
The Browser plugin was unavailable, so local headless Chrome with Playwright
was used at desktop 1440×1000 and mobile 390×844 sizes.

- Flower photos loaded; desktop catalog, mobile storefront, AI page, and mobile
  checkout had no horizontal page overflow.
- Customer email sign-in, product quick-add, and cart checkout worked.
- A cash order was created as unpaid, with no card charge.
- A test-card order stayed pending until the explicit test payment action,
  then became paid. No real money was charged.
- Django admin cash collection removed the order from the unpaid-cash queue.
  The resulting payment history was visible and contained no editable inputs.
- Admin attention filters and payment-history row readability were inspected.
- An OAuth callback without a code displayed a recoverable sign-in error,
  not an indefinite spinner. StrictMode single-use exchanges and refresh races
  are covered by automated tests.
- Disabled AI configuration showed an unavailable/support message. Enabled
  advice and mobile layout were checked with mocked responses. No paid Gemini
  or Tavily requests were made. Provider payloads, privacy boundaries, failures,
  and rate limits are covered by automated tests.
- No JavaScript page errors were recorded during these browser checks.

## Live configuration still required

Google Cloud navigation was stopped by the computer-use safety rules because
the active Yandex browser is unsupported. No Cloud project, credentials, billing,
or provider account was created or changed.

Before completing live setup, provide the Google Cloud project and deployment
URLs, choose Payme or Click (Stripe remains a disabled placeholder), and confirm
the merchant account is available. Sign in yourself; do not paste secrets into
chat. New persistent credentials require confirmation at creation time.

Gemini/Tavily code is implemented but disabled by default. Backend secrets,
billing limits, and approval to enable the flower-shopping helper are still
needed. See [deployment configuration](DEPLOYMENT.md#optional-gemini-flower-advice-and-tavily-search).

Real OAuth consent, merchant sandbox certification, live charges, refunds, and
provider settlement reconciliation were not tested. Passing local tests is not
a claim that those live workflows are configured or certified.
